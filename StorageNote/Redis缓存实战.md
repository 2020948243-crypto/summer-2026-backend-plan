## Redis缓存实战笔记

### 五大基础数据结构

#### String
- 常用命令：SET, GET, INCR, DECR, APPEND
- 应用场景：缓存热点数据、计数器、Session存储

#### Hash
- 常用命令：HSET, HGET, HMSET, HMGET, HGETALL
- 应用场景：存储对象、用户信息

#### List
- 常用命令：LPUSH, RPUSH, LPOP, RPOP, LRANGE
- 应用场景：消息队列、最新列表

#### Set
- 常用命令：SADD, SMEMBERS, SINTER, SUNION, SDIFF
- 应用场景：去重、共同好友、抽奖

#### ZSet
- 常用命令：ZADD, ZRANGE, ZREVRANGE, ZSCORE, ZRANK
- 应用场景：排行榜、延迟任务

### 缓存三大问题

#### 缓存穿透
- 问题：查询不存在的数据，请求直达DB
- 解决方案：
  - 布隆过滤器
  - 缓存空值
  - 接口限流

#### 缓存击穿
- 问题：热点key过期，大量请求直达DB
- 解决方案：
  - 设置热点key永不过期
  - 互斥锁更新
  - 提前预热

#### 缓存雪崩
- 问题：大量key同时过期，DB压力骤增
- 解决方案：
  - 过期时间随机化
  - 多级缓存
  - 服务降级

### Redis实现登录态

#### Session方案
- 用户登录成功后生成Token
- Token作为key，用户信息作为value存入Redis
- 设置过期时间，支持续期
- 退出登录时删除Redis中的Token

#### 实现要点
- Token生成策略（UUID/JWT）
- 过期时间设置
- 续期机制（每次访问刷新过期时间）

### 热点数据缓存

#### 策略
- 读多写少的数据适合缓存
- 设置合理的过期时间
- 采用LRU/LFU淘汰策略

#### 实现步骤
1. 查询时先查缓存
2. 缓存命中直接返回
3. 缓存未命中查DB
4. 将DB结果写入缓存
5. 返回结果

### 缓存与数据库一致性

#### 更新策略
- 先更新DB，再删除缓存（推荐）
- 先删除缓存，再更新DB（可能导致脏数据）

#### 最终一致性
- 定期同步
- 消息队列异步更新
- 订阅DB binlog
